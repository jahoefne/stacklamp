# Geometry contract

`types.ts` is frozen. The engine (B) and the app (C1/C2/C3) compile against it; changes go through the orchestrator and are logged below.

## Semantics
- Units mm, z-up, lamp axis = z, floor at z = 0.
- Every `PartMesh` is in its **print frame**: centred on the origin, bed at z = 0, as it should be sliced. `DerivedDims.placements[id]` holds one column-major 4×4 per copy mapping print frame → world (assembled lamp). The cover is printed plate-down and flipped by its placement. `fit-test` has no placements.
- Band index 0 = bottom segment. `ColourPlan.inner/outer` are already fitted to `inner.count` / `outer.count`.
- `deriveDims(params)` is synchronous, pure TypeScript, < 1 ms, **never throws**: invalid combinations become `messages` with severity `error` and `ok = false`. It runs on the main thread on every edit; the worker re-derives from `params` itself.
- `defaultParams()` returns a fresh object. `PARAM_META` lists every `NumericParamPath` exactly once with label/unit/range/step/precision/group/advanced.
- `partsKey(params)` is a string that changes only when a mesh or its mass estimate would change (the printer preset alone does not; the nozzle does, through the layer height and shells the specs carry).
- `computeBom(parts, dims, plan)` is pure (density 1.27 g/cm³, 1.75 mm filament).
- `createGeometryClient()` spawns the worker; `buildParts(p, 'preview')` coalesces newest-wins (a superseded call rejects with an error whose `name` is `'SupersededError'`, which the UI ignores); `exportZip` runs FIFO; downloads always use export quality.
- ZIP entries: `base.3mf`, `inner-segment.3mf`, `outer-segment.3mf`, `top-cover.3mf`, `plate-clamp.3mf`, optional `fit-test.3mf` (or `.stl` for all when format is `stl`), `PRINT-PLAN.md`, `ASSEMBLY.md`, `config.json`. Nothing else.
- `config.json` contains `{ app: 'stacklamp', schema: 1, generated, shareUrl, params, derived: {…key numbers} }` and round-trips through `parseConfig`.
- Performance budgets: preview build of all parts ≤ 500 ms, export-quality base ≤ 2 s (M-series laptop). Preview revolves use 128 circular segments; export ≥ 192.
- `src/geometry` and `src/export` must not touch DOM or Node globals (they run in the worker, in Node tests and in a future CLI). Only `src/worker/geometry.worker.ts` imports the wasm URL.

## Changelog
- 2026-10-22 v1 frozen by the orchestrator.
- 2026-10-22 engine landed (barrel now real). Additions, no breaking changes: extra message codes (`tubes-too-close`, `base-too-small`, `wire-no-room`, `screw-vs-collar`, `invalid-number`, `out-of-range`, `outer-slits-dropped`); always-on info at defaults (`base-height-raised`, `screw-height-raised`, `pocket-needs-supports` without a path); `fit-test` has `copies = 2` (two rings to push together); `computeBom` metres come from the realistic mass estimate; `config.json` also carries `appVersion` and `colourPlan`; barrel also exports `FILAMENT_DIAMETER_MM`, `MESSAGE_CODES`, `MessageCode`, `isBenignGeometryError`, `parseConfig`, `ConfigFile`. Locked mode uses `N = floor((A + 0.5) / P)` so the auto→locked round trip holds; `buildParts` never returns the fit test and still builds under bed-fit errors.
- 2026-10-22 slice-QA fixes (engine): `PRINTER_PRESETS['bambu-256']` is now 256 × 256 × **250** (X1C/P1S printable height; only the A1 reaches 256), label "Bambu Lab P1S / X1C / A1 (256 × 256 × 250)", and `defaultParams().printer.bedZ = 250`; the A1 mini label reads "(180 × 180 × 180)". ZIP file name now `stacklamp-L{L}-D{outerOD}-{rod|tube}-o{N}x{H}-i{N}x{H}.zip`. `PartMesh.massGrams.estimate` is the slicer-calibrated printed mass (vase lines with rounded flanks for segments/fit test; walls + 20 % infill via an eroded profile for base and cover; base includes ≈ 8 % of the pocket volume as tree supports), within ~4 % of Bambu Studio slices; `solid` is unchanged.
- 2026-10-22 plate clamp (engine + app): new `PartId` **`plate-clamp`** (in `PART_IDS` and `ASSEMBLY_PART_IDS` after `top-cover`, label "Plate clamp", ZIP entry `plate-clamp.3mf`, one copy, placed by `placements['plate-clamp']` with no flip). The base's plate pocket is now `plate.thickness + 3 (clamp) + tolerances.plateDepth` deep and a boss of `plate.bore − 2·plateRadial` hangs from its ceiling through the plate's bore, with a blind pilot hole of `base.screwDiameter` for one countersunk wood screw; the clamp (a Ø `bore + 20` × 3 mm disc with a countersunk hole) is pulled onto the boss and holds the plate when the lamp is lifted. `DerivedDims.base` gains `bossDiameter`, `clampDiameter`, `clampScrewLength` and `clampRecess` (additions). `partsKey` now changes with `plate.bore`. The base is 3 mm taller at the defaults (46 mm, 81 mm print height).
- 2026-10-22 nozzle (engine + app): `LampParams.printer` gains **`nozzle: NozzleId`** (`'0.4' | '0.6' | '0.8'`, default `'0.6'`); `EnumParamPath` gains `printer.nozzle` (URL key `nz`, codes `4 6 8`). The barrel exports `NOZZLES` (per nozzle: `label`, `diameter`, default `wall` = the vase line width 0.5 / 0.8 / 1.0, `wallRange` 0.35–0.6 / 0.5–1.0 / 0.7–1.3, `layer` 0.2 / 0.3 / 0.4, `fineLayer` 0.2 / 0.2 / 0.24 for the cover, `lineWidth` 0.42 / 0.62 / 0.82), `NOZZLE_IDS` and `nozzleOf(params)` (an unknown id reads as 0.6). The app's `applyNozzle(id)` (also `setEnum('printer.nozzle', …)`) sets the nozzle and `segments.wall` to its line width; the codec treats that wall as the nozzle-implied default, so `nz=4` alone is a 0.5 mm wall and links without `nz` keep meaning the 0.6 mm nozzle. `vase-wall` now warns outside `wallRange` and names the neighbouring nozzle. PRINT-PLAN.md states the nozzle, the layer heights (segments and base at `layer`, cover at `fineLayer`), the base's top/bottom shell layers (≈ 1.5 mm in whole layers: 8 / 5 / 4) and the Arachne note per nozzle; `config.json` carries `printer.nozzle` and `parseConfig` reads older files as 0.6. `SegmentSpec` gains `layer`, `BaseSpec` and `CoverSpec` gain `shell` (walls, top/bottom, infill from `src/geometry/print.ts`) for the mass estimates, so `partsKey` and the part cache keys change with the nozzle (a rebuild, not a new mesh). `scripts/slice-check.sh` slices with the nozzle's Bambu machine and Standard process; the estimates are within 5 % of those slices on all three nozzles (the cover models the bridged first layer over its sparse core).
- 2026-10-23 segment forms (engine + app). Each segment's body between its shoulder and the next segment's socket can take a **form**; the joint never changes. `types.ts` gains `FormId` (`straight | drop | ball | waist | barrel | star | flute | twist`) and `FORM_IDS`; `LampParams` gains `tubes.innerFormOD` / `tubes.outerFormOD` (the widest point of bulging forms per stack; waists narrow by the same amount; defaults 90 / 240), `segments.maxOverhang` (degrees from vertical, default 45, advanced) and `forms: { inner: FormId[]; outer: FormId[] }` (stored bottom → top, any length, fitted to the count by `fitForms` like the colour bands; `[]` = all straight, so the default lamp is unchanged). `ParamMeta.unit` adds `'°'`. `SegmentDims` gains `forms` (fitted) and `maxOD` (the stack's footprint; `fit[id].size` uses it). **`PartMesh` gains `form?`**: a segment stack now yields one `PartMesh` per distinct form in use, all with the same `id`, each with the copies that form needs (`PartSpecs.variants` lists them; `DerivedDims.inner/outer.forms[k]` says which band gets which; `placements[id][k]` is still per band). `BomPartRow` gains `form?`. ZIP entries for a form other than straight are `inner-segment-<form>.3mf` (straight keeps `inner-segment.3mf`); the print plan lists one row per file and, when a stack has a form, the per-band order with form and colour. New message codes `form-too-wide`, `form-too-narrow` (errors: 2 mm radial rules against the other stack, the rod and the bed) and `form-squeezed` (warning: a short segment scales the form down). Share link keys `fi` / `fo` (one form code per band, written only when not all straight), `ifd`, `ofd`, `mo`; `config.json` carries the new params and `parseConfig` reads older files as straight. The barrel exports `FORMS`, `DEFAULT_FORM`, `fitForms`, `formsEqual`, `isFormId`, `formByCode`, `allStraight`. `partsKey` changes with the forms in use and the form diameters (through the variants), not with a form diameter while every form is straight.
- 2026-10-23 segment forms, details after the implementation: `PartSpecs.variants` drives the worker (`meshJobs(specs, counts, ids)` in handler.ts: one job per variant, copies = its bands); the straight segment's cache key is `inner-segment#straight|…`; `DEFAULT_CACHE_SIZE` is 16. Export progress is one step per mesh (the stage repeats the part id for every form), then `docs`, `zip`, `zip`; `total` = meshes + 2. `DocInput.files` is a `ReadonlyMap<PartMesh, string>`, `partFile(mesh, req, dims)` takes the dims, `bundleEntryNames(format, fit, forms?)` takes the fitted forms per stack; a form's 3MF carries `stacklamp:form`, its name "Inner segment (Ball)" and the dominant colour of that form's bands; the print plan replaces "Colour order" with "Segment order (bottom → top)" (band, form, colour, file) only when a stack has a form. `BomPartRow.file` is the stem (`inner-segment-ball`) and every segment row carries `form` (also `'straight'`). Geometry (profiles/forms.ts): a form diameter at or below the tube diameter builds straight with no message; the twist is also limited by the lean of its turning ribs, so it can be squeezed (warning) even in a long zone (the 240 mm outer default reaches ≈ 229 mm); a waist never goes deeper than `wall + 1 mm` from the axis; besides the stack-against-stack, rod and bed rules, derive checks a waist on the bottom inner segment against the rod collar, on the top inner segment against the cover boss, and the top segments against the cover's capture ring. The preview keys geometries by `meshKey(id, form)` and gives band k the mesh of `forms[k]`, falling back to the straight mesh while a rebuild is in flight; the exploded view and the framing use `maxOD`. The schematic fallback still draws straight tubes.
